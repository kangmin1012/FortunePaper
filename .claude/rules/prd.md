## 1. 제품 개요

**포춘페이퍼(FortunePaper)** 는 사주(생년월일 + 성별)를 기반으로 오늘의 운세를 매일 **한 장의 리포트** 형식으로 발행하는 모바일 앱이다.

| 항목 | 내용 |
|------|------|
| 패키지명 | `com.fortune.paper` |
| 플랫폼 | Android · iOS (동시 출시) |
| 핵심 가치 | "오늘 하루를 여는 30초 리추얼" |
| 차별점 | 텍스트 나열이 아닌 **신문 1면 형식** — 날씨 등급 한 장으로 하루의 기운을 직관적으로 전달 |
| 수익 모델 | **완전 무료** (v1), 출시 후 반응 보고 유료화 검토 |
| 언어 | 한국어 (v1) |

## 2. 타겟 사용자 & 페르소나

### 페르소나 ① — 채연 (29세, 마케터)

> "출근 전에 딱 한 줄만 봐도 기분이 달라져요."

- 매일 아침 루틴이 있고, 짧고 긍정적인 콘텐츠를 선호
- 점성술·타로 앱을 써봤지만 내용이 너무 길고 광고가 많아 지침
- **원하는 것**: 알림 한 번 → 오늘의 날씨 운세 확인 → 앱 종료. 30초 이내

### 페르소나 ② — 준호 (34세, 프리랜서 디자이너)

> "하루 시작할 때 기준점 같은 게 있으면 좋겠어요."

- 규칙적인 출퇴근이 없어 하루의 리듬을 만들어줄 콘텐츠가 필요
- 앱의 시각적 완성도를 중시, UI가 촌스러우면 바로 삭제
- **원하는 것**: 매일 저녁 내일의 운세 미리 확인, 비주얼이 담긴 리포트

## 3. 핵심 사용자 경험

### 사용자 여정

```
최초 실행 (가입·로그인 없음)
 └─ 온보딩: 이름 + 생년월일 + 성별 (+ 태어난 시각 선택) 입력
 └─ 알림 시각 설정 (기본: 07:30)
 └─ 곧바로 메인 화면 진입 — 모든 정보는 기기 로컬(DataStore)에 저장

매일 반복
 └─ 알림 수신 → 앱 열기
 └─ 오늘의 리포트 확인 (날씨 등급 + 한 줄 요약 + 조언)
 └─ 앱 종료

선택
 └─ 설정 → 내 정보 수정 (이름·생년월일·성별·시진)
 └─ 설정 → 알림 시각 변경 또는 알림 끄기
 └─ 설정 → 정보 초기화 (온보딩으로 복귀)
```

### 골든 패스

> **알림 수신 → 앱 열기 → 오늘의 날씨 운세 한 장 확인** (목표: 30초 이내)

## 4. 기능 명세

### 4.1 로컬 프로필 (계정 없음)

> **v1.1 변경**: 카카오 로그인 및 서버 계정(Supabase Auth)을 제거했다. 계정·로그인 개념이 없다.

| 항목 | 내용 |
|------|------|
| 저장 위치 | 온보딩 수집 정보(이름·생년월일·성별·시진·알림설정) 전부 기기 로컬 **DataStore**에 저장 |
| 첫 실행 | 로컬 프로필 없음 → 온보딩으로 이동 |
| 재실행 | 로컬 프로필 존재 → 리포트 화면으로 바로 이동 |
| 수정 | 설정 화면에서 프로필 수정 가능 (§4.5) |
| 초기화 | 설정 → 데이터 초기화: 로컬 데이터 전체 삭제 + 알림 취소 → 온보딩 복귀 |
| 한계 | 계정이 없으므로 기기 변경·앱 삭제 시 데이터 이전 불가 (수용, §12 향후 검토) |

### 4.2 온보딩 (첫 실행 7단계 플로우)

> 디자인 기준: `design/FortunePaper_Design/Onboarding.html` · `screens.jsx`. 단일 스텝 플로우로 진행되며, 마지막 단계 완료 시 곧바로 메인 화면으로 진입한다.

| 단계 | 화면 | 입력값 | 필수 |
|------|------|--------|------|
| 0 | Welcome | (브랜드 소개 + "시작하기" 버튼) | — |
| 1 | Value | (가치 제안 3카드, 입력 없음) | — |
| 2 | Name | 이름 (최대 12자) | 필수 |
| 3 | Birth | 생년월일 (YYYY-MM-DD, 휠 피커) | 필수 |
| 4 | Gender | 성별 (남/여) | 필수 |
| 5 | Time | 태어난 시각 (12시진 자~해) | **선택** (건너뛰기 가능) |
| 6 | Notify | 알림 시간 (프리셋 06:30/07:30/08:30/09:30) | 필수 |

| 항목 | 내용 |
|------|------|
| 목적 | 이름은 리포트 인사말·알림 표시용, 생년월일·성별·시각은 사주 계산에 전달 |
| 필수 여부 | 이름·생년월일·성별 필수(미입력 시 다음 진행 불가), 태어난 시각만 선택 |
| 저장 | 모든 입력값은 완료 시점에 DataStore에 저장 (서버 미전송) |
| 알림 시간 | 온보딩 마지막 단계에서 수집하여 `notify_time`에 저장, 완료 직후 알림 권한 요청 + 로컬 알림 예약 |
| 수정 | **설정 → 프로필 수정**에서 변경 가능 (v1.1에서 "탈퇴 후 재가입" 정책 폐기) |
| 온보딩 완료 판단 | 별도 플래그 없이 필수 3종(이름·생년월일·성별)의 로컬 존재 여부로 판단 |

> **결정 (디자인 우선, 2026-06-02 갱신)**: 태어난 시각(12시진)을 v1에서 **선택 입력으로 수집**한다. 미입력 시 Claude가 대표값(정오)으로 계산하도록 프롬프트 처리. 정밀 사주(분 단위)는 향후 유료 기능 후보.

### 4.3 오늘의 리포트 (메인 화면)

리포트는 하루 1회 생성된다. 자정(00:00 KST) 기준으로 새 날짜의 리포트가 생성되고 로컬 캐시가 교체된다. 캐시에 저장된 `date`가 오늘(KST)과 다르면 재생성한다.

> **예외 (v1.1)**: 설정에서 사주 입력값(생년월일·성별·시진)을 수정하면 당일 캐시를 무효화하고 다음 진입 시 재생성한다. 이름만 수정한 경우는 캐시를 유지한다.

| 구성 요소 | 내용 |
|----------|------|
| 날씨 등급 | 5단계 날씨 아이콘 + 텍스트 (대형, 한 눈에 들어와야 함) |
| 한 줄 요약 | AI가 생성하는 오늘의 종합운 헤드라인, **20자 이내** |
| 오늘의 조언 | AI의 한 마디, **50자 이내** |
| 새로고침 | 수동 새로고침 가능 (캐시 반환, 당일 재생성 없음) |
| 로딩 상태 | 첫 생성 중일 때 스켈레톤 UI 표시 |
| 오류 상태 | 생성 실패 시 안내 메시지 + 재시도 버튼 |
| 한도 초과 | Gemini 무료 티어 한도(429) 도달 시 전용 다이얼로그 "오늘 하루 용지가 다 떨어졌어요😢 / 용지를 채우고 내일 다시 올게요!" (브랜드 톤). 닫은 뒤에도 인라인 안내 + 재시도 유지 |

### 4.4 로컬 알림

> **v1.1 변경**: 서버 푸시(FCM + pg_cron) 대신 기기 로컬 알림을 사용한다. 서버 인프라 불필요.

| 항목 | 내용 |
|------|------|
| 기본값 | 온보딩 마지막 단계(Notify)에서 프리셋 선택, 기본 07:30 |
| 조정 | 분 단위 시각 지정 가능 |
| 끄기 | `notify_enabled` 토글 — 끄더라도 `notify_time`은 보존되어 다시 켤 때 복원 |
| 내용 | **고정 문구만** (예: "오늘의 포춘페이퍼가 도착했어요 📰") — 발송 시점에 당일 운세가 아직 생성 전이므로 등급 포함 불가 |
| 발송 방식 | Android: `AlarmManager.setAndAllowWhileIdle`(inexact, 수 분 오차 수용) + 발송 후 재예약 + 재부팅 시 재예약. iOS: `UNCalendarNotificationTrigger(repeats: true)` |
| 권한 | 온보딩 완료 직후 요청 (Android 13+ `POST_NOTIFICATIONS`, iOS `requestAuthorization`). 거부해도 온보딩은 완료 처리, 설정에서 재안내 |

### 4.5 설정

| 항목 | 내용 |
|------|------|
| 내 정보 (프로필 수정) | **(v1.1 신규)** 이름·생년월일·성별·태어난 시각 수정. 사주 입력값(생년월일·성별·시진) 변경 시 당일 운세 캐시 무효화 → 재생성 |
| 알림 시간 변경 | 시간 피커 UI, 변경 즉시 저장 + 로컬 알림 재예약 |
| 알림 끄기/켜기 | 토글 (`notify_enabled`) — 끄면 알림 취소, 켜면 재예약 |
| 정보 초기화 | **(v1.1, 로그아웃·회원 탈퇴 대체)** 확인 다이얼로그 → 로컬 데이터 전체 삭제 + 알림 취소 → 온보딩으로 이동 |
| 앱 버전 | 하단에 버전명 표기 |

> 디자인 기준: `design/FortunePaper_Design/Settings.html` · `settings.jsx` (2026-06-10 갱신 — 내 정보/알림 설정/정보 초기화 3항목 + `ProfileEditScreen`). UI 라벨은 시안의 "내 정보"·"정보 초기화"를 따른다.

## 5. 등급 시스템 — 날씨 5단계

운세의 강도를 날씨로 직관적으로 표현한다. **숫자·알파벳 등급 없음**.

| 코드 | 표시 | 아이콘 | 톤 가이드 |
|------|------|--------|-----------|
| `SUNNY` | 화창 | ☀️ | 적극적으로 도전하세요. 모든 게 잘 풀리는 날. |
| `CLEAR` | 맑음 | 🌤️ | 좋은 흐름이에요. 중요한 일을 오늘 처리하세요. |
| `CLOUDY` | 구름 | ☁️ | 평온한 하루. 무리하지 말고 꾸준하게. |
| `RAINY` | 비 | 🌧️ | 조심이 필요해요. 그래도 괜찮아질 거예요. |
| `STORM` | 폭풍번개 | ⛈️ | 힘든 날이지만 지나갑니다. 오늘만큼은 쉬어가도 돼요. |

**톤 원칙**

- 모든 등급에서 **위협·공포·부정적 판단 금지**. 폭풍번개도 위로와 격려로 끝낸다.
- "나쁘다"가 아닌 "조심이 필요하다"로 표현한다.
- 한국어 반말 금지 — 모든 문구는 존댓말로 작성한다.

### Claude API 응답 스펙 (업데이트)

```json
{
  "grade": "SUNNY",
  "summary": "모든 일이 술술 풀리는 날이에요",
  "advice": "망설였던 일을 오늘 시작해보세요. 타이밍이 완벽합니다."
}
```

- `grade` 허용값: `SUNNY | CLEAR | CLOUDY | RAINY | STORM`
- `summary`: 20자 이내 한국어 종합운 한 문장
- `advice`: 50자 이내 한국어 오늘의 조언

> 기존 `architecture.md`의 `grade` 허용값 (`S | A | B | C | D`)은 이 스펙으로 교체된다.

## 6. 비기능 요구사항

| 항목 | 기준 |
|------|------|
| 응답 속도 | 메인 화면 진입 후 **캐시 리포트 1초 이내** 표시 |
| 가용성 | Edge Function 실패 시 사용자 친화적 에러 메시지 + 재시도 버튼 |
| 데이터 보관 | 운세는 **로컬 캐시 1일 보관** — 새 날짜 리포트 생성 시 캐시 교체. 서버에는 어떤 유저 데이터도 영속 저장하지 않음 |
| 개인정보 | 모든 유저 정보는 기기 내(DataStore) 저장. 서버 전송은 운세 생성 요청 시 생년월일·성별·시진을 일회성으로 전달할 뿐 서버에 저장하지 않음. 제3자 제공 없음 |
| 접근성 | 날씨 등급은 아이콘만이 아닌 **텍스트(화창/맑음/...)도 병기** |
| 다국어 | 한국어 전용 (v1) |

## 7. 기술 스택 요약

| 레이어 | 기술 |
|--------|------|
| 앱 | Compose Multiplatform (KMP) |
| 로컬 저장 | DataStore (androidx.datastore preferences, KMP) — 유저 프로필·알림 설정·운세 캐시 |

| DI | Koin |
| 이미지 | Coil (KMP) |

## 8. 데이터 모델 요약

> **v1.1 변경**: 서버 DB(`users`·`fortunes` 테이블)를 제거하고 전부 기기 로컬 DataStore로 전환했다.

### 로컬 데이터 스키마 (DataStore — `fortune_paper.preferences_pb`)

| 키 | 타입 | 설명 |
|----|------|------|
| `profile_name` | String | 표시 이름, 리포트 인사말·알림용 (필수, 최대 12자) |
| `profile_birth_date` | String | 생년월일 YYYY-MM-DD, 사주 계산용 (필수) |
| `profile_gender` | String | `MALE` / `FEMALE` (필수) |
| `profile_birth_time` | String? | 태어난 시각 12시진 (`자`~`해`), 미설정 시 서버가 정오 대표값 처리 (선택) |
| `notify_enabled` | Boolean | 알림 토글 (기본 true) |
| `notify_time` | String | 알림 시각 HH:mm (기본 07:30) |
| `fortune_cache_json` | String | 당일 운세 캐시 — `{ date, grade, summary, advice }` JSON. `date`(KST)가 오늘과 다르면 무효 |

> 리포트 생성 흐름 및 레이어 배치 → [`.claude/rules/architecture.md`](../.claude/rules/architecture.md) 참조

| Material3 기반 | 커스텀 디자인 도입 전까지 Material3 토큰 사용 |
